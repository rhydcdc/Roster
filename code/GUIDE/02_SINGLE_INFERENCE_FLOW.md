# 단일 요청 추론 (`B = 1`) 전체 흐름 (직관 가이드 · 소규모 예시)

> **문서 목적:** [01_TRAINING_FLOW.md](01_TRAINING_FLOW.md)에서 학습을 마친 `CH2` 모델(`CH2_M32_B1B2_r9`)에 **새 토큰 1개**(`B = 1`, 개인 PC · LLM 생성 단계)가 들어왔을 때, 실제로 어떻게 계산해서 **6배 넘게 빨라지는지** 똑같은 8뉴런·4중심점 예시로 이어서 설명하는 문서다.

| 항목 | 베이스 모델 (`s1_seed2`, 다 켬) | 우리 `CH2` 모델 (`B = 1` 실측) |
|---|---|---|
| **시험 정확도** (`10,000장`, 통과선 `90.52%`) | **91.02%** (`100%` 뉴런 켬) | **90.81%** (베이스의 99.77%) |
| **평균 켜는 뉴런 (`K`)** | `100%` (`4,096 × 4층`) | 전체 `13.52%` · 실측 32토큰 표본 `15.0%` |
| **RTX 4060 실측 (`d = 1,024`, 4층 합)** | `0.4656 ms` (`1.00×`) · `0-Mask 0.99×` | **`0.0751 ms` (`6.20×`)** |
| **RTX 4060 실측 (`d = 4,096`, 4층 합)** | `1.7705 ms` (`1.00×`) · `0-Mask 0.99×` | **`0.2824 ms` (`6.27×`)** *(이론 `6.67×`의 94%)* |

---

## 출발점: 학습이 끝난 뒤 메모리에 이미 저장된 것 3가지

[01_TRAINING_FLOW.md](01_TRAINING_FLOW.md)의 학습과 배포 준비가 끝나면, 추론을 시작하기 전에 모델 안에는 아래 3가지가 고정되어 들어 있다.

1. **고정된 중심점 좌표 4개** *(층마다 따로 보관, 실제 `CH2`는 앞 3층 32개 · 4층 256개)*:
   - 중심점 `A`: `(1.1, 1.0)` · 중심점 `B`: `(2.1, 1.4)` · 중심점 `C`: `(-1.1, -1.1)` · 중심점 `D`: `(-2.1, -0.7)`
2. **확정된 출석부 (중심점별 켤 뉴런 번호표):**
   - 중심점 `A`: `{N1, N2, N5, N7}` (`K = 4`)
   - 중심점 `B`: `{N1, N2, N5, N7}` (`K = 4`)
   - 중심점 `C`: `{N4, N6, N8}` (`K = 3`)
   - 중심점 `D`: `{N4, N6, N8}` (`K = 3`)
   - *(학습이 끝난 중심점에는 이 `K`개 번호만 남아 있으며, 중심점 `A`에 배정되는 모든 토큰은 종류와 무관하게 항상 똑같은 4개 뉴런을 켠다.)*
3. **FFN 가중치 행렬 3개 (`W_gate, W_up, W_down`):**
   - 뉴런 1개마다 `W_gate` 1줄, `W_up` 1줄, `W_down` 1줄씩 총 3줄의 가중치가 들어 있다.
   - *(실제 GPU 메모리에서는 `W_gate`와 `W_up`의 같은 뉴런 줄을 나란히 붙여 보관하고, 5단계에서 확정된 블록 순서대로 미리 재배치해 두었다.)*

## 1단계 · 중심점 연산: 새 토큰이 어느 방인지 1번에 찾기

새 **토큰 `T_new`**(새 사진 1장, 또는 LLM의 새 단어 토큰 1개)가 이 층에 들어왔고, 정규화한 좌표가 `(1.3, 0.9)`라고 하자.

신경망 라우터(작은 MLP)를 돌리지 않고, 고정된 중심점 4개와의 **거리 제곱**(실제 계산은 단순 내적 1회)만 잰다.

| 중심점 (구역) | 대표 좌표 | `T_new (1.3, 0.9)`와의 거리 제곱 | 결과 |
|---|---:|---:|---|
| **중심점 `A`** | `(1.1, 1.0)` | `(1.3−1.1)² + (0.9−1.0)² =` **`0.05`** | **가장 가까움 → `A` 당첨!** |
| 중심점 `B` | `(2.1, 1.4)` | `(1.3−2.1)² + (0.9−1.4)² = 0.89` | |
| 중심점 `C` | `(-1.1, -1.1)` | `(1.3+1.1)² + (0.9+1.1)² = 9.76` | |
| 중심점 `D` | `(-2.1, -0.7)` | `(1.3+2.1)² + (0.9+0.7)² = 14.12` | |

- **계산 부담이 거의 `0`인 이유:** 실제 `CH2` 1~3층은 중심점이 32개뿐이라, 입력 벡터와 `32`개 대표 좌표의 내적 1번(`32 × d`)만 하면 끝난다. 이는 FFN 전체 계산량의 **0.2% 미만**이며, 실제 LLM에서는 그 층의 **어텐션에 들어가기 직전 입력으로 어텐션과 동시에 미리 계산**해 기다리는 시간 자체를 없앤다.

## 2단계 · 출석부 조회: 계산 전에 '안 읽을 뉴런'부터 통째로 제외

방금 고른 중심점 **`A`의 출석부**를 열면 켤 뉴런 4개가 바로 나온다.
- **켤 뉴런 (`ON`):** `N1, N2, N5, N7` (4개)
- **끌 뉴런 (`OFF`):** `N3, N4, N6, N8` (4개)

여기서 **단순 0-마스킹**(`0-Mask` 대조군)과 **우리 `Roster`의** 결정적 차이가 갈린다.

| 방식 | DRAM에서 읽어 오는 가중치 | 실제 곱셈하는 뉴런 | RTX 4060 실측 (`d = 4,096`) |
|---|---|---|---|
| **베이스 모델 (다 켬)** | `N1 ~ N8` **8개 전부** (`100%`) | 8개 전부 | `1.7705 ms` (`1.00×`) |
| **단순 `0-Mask` 대조군** | `N1 ~ N8` **8개 전부 읽고** 결과에만 `× 0` | 8개 전부 계산 후 버림 | `1.7800 ms` (**`0.99×`, 효과 0**) |
| **우리 `Roster`** | **`N1, N2, N5, N7` 4개만 선택 읽기** | **4개만 계산 (`W_gate·up·down` 전부 스킵)** | **`0.2824 ms` (`6.27×`)** |

- FFN을 시작하기 **전에** 이미 켤 뉴런 번호표가 확정되어 있으므로, 꺼진 뉴런 4개는 `W_gate`, `W_up`, `W_down` **세 행렬 모두에서 메모리(DRAM) 읽기 자체를 아예 건너뛴다.**

## 3단계 · 켠 뉴런 4줄만 꺼내 FFN 계산 (`gate·up` → `down`)

이제 GPU가 실제로 하는 일은 **출석부에 적힌 4줄만 메모리에서 꺼내 계산하는 2단계**뿐이다.

| 뉴런 번호 | `A` 출석부 | 1단계 (`W_gate, W_up` 읽기 → 활성값 `a`) | 2단계 (`W_down` 열 벡터 읽기 → 출력 합산) |
|:---:|:---:|---|---|
| **`N1`** | **ON** | `W_gate[1], W_up[1]` 읽어 `a1` 계산 | `W_down[:, 1]` 읽어 `a1 · w1` 더함 |
| **`N2`** | **ON** | `W_gate[2], W_up[2]` 읽어 `a2` 계산 | `W_down[:, 2]` 읽어 `a2 · w2` 더함 |
| `N3` | OFF | *읽지 않음 · 계산 안 함* | *읽지 않음 · 계산 안 함* |
| `N4` | OFF | *읽지 않음 · 계산 안 함* | *읽지 않음 · 계산 안 함* |
| **`N5`** | **ON** | `W_gate[5], W_up[5]` 읽어 `a5` 계산 | `W_down[:, 5]` 읽어 `a5 · w5` 더함 |
| `N6` | OFF | *읽지 않음 · 계산 안 함* | *읽지 않음 · 계산 안 함* |
| **`N7`** | **ON** | `W_gate[7], W_up[7]` 읽어 `a7` 계산 | `W_down[:, 7]` 읽어 `a7 · w7` 더함 |
| `N8` | OFF | *읽지 않음 · 계산 안 함* | *읽지 않음 · 계산 안 함* |

1. **1단계 (`gate · up`):** 켠 뉴런 4개(`N1, N2, N5, N7`)의 가중치 줄만 읽어 `a_compact = [a1, a2, a5, a7]` 4개 숫자만 빽빽하게 만들어 둔다.
2. **2단계 (`down`):** 방금 만든 숫자 4개에 대응하는 `W_down` 4줄만 읽어 **`a1·w1 + a2·w2 + a5·w5 + a7·w7`을** 구하고, 원래 잔차 `h`에 더해 다음 층으로 넘긴다.

<details>
<summary><b>참고 · 원래처럼 쭉 읽지 않고 선택해서 긁어 오면(gather) 오버헤드가 크지 않나? (메모리 저장 방식 + 3상황 비교)</b></summary>

**오버헤드는 약 6%에 불과하며, 이 선택 읽기 비용까지 전부 포함해 RTX 4060에서 `6.20 ~ 6.27×`를 실측했다.**

**① 메모리에 이렇게 미리 저장해 둔다 (`W_gu` · `W_dn` 물리 배치):**
- `W_gu`: 뉴런 1개마다 `W_gate` 1줄과 `W_up` 1줄을 **한 줄로 나란히 붙여** 저장 (`[gate | up]`, 길이 `2d = 4 ~ 16 KB`)
- `W_dn`: 뉴런 1개마다 `W_down` 열 벡터 1줄을 **연속으로** 저장 (길이 `d = 2 ~ 8 KB`)
- 5단계에서 확정된 **블록 순서대로** 뉴런 줄 자체를 미리 재배치해 저장해 둔다.

| 저장된 메모리 줄 순서 | `W_gu` 한 줄 (`[gate \| up]`, `4 ~ 16 KB`) | `W_dn` 한 줄 (`[down]`, `2 ~ 8 KB`) | 중심점 `A`일 때 GPU 동작 |
|:---:|---|---|---|
| **0번 줄 (`N1`)** | `[ g1_0 … g1_d \| u1_0 … u1_d ]` *(연속 32~128박스)* | `[ d1_0 … d1_d ]` *(연속 16~64박스)* | **번호표 `0` 보고 한 줄 통째로 연속 읽기** |
| **1번 줄 (`N2`)** | `[ g2_0 … g2_d \| u2_0 … u2_d ]` *(연속 32~128박스)* | `[ d2_0 … d2_d ]` *(연속 16~64박스)* | **번호표 `1` 보고 한 줄 통째로 연속 읽기** |
| **2번 줄 (`N5`)** | `[ g5_0 … g5_d \| u5_0 … u5_d ]` *(연속 32~128박스)* | `[ d5_0 … d5_d ]` *(연속 16~64박스)* | **번호표 `2` 보고 한 줄 통째로 연속 읽기** |
| **3번 줄 (`N7`)** | `[ g7_0 … g7_d \| u7_0 … u7_d ]` *(연속 32~128박스)* | `[ d7_0 … d7_d ]` *(연속 16~64박스)* | **번호표 `3` 보고 한 줄 통째로 연속 읽기** |
| 4~7번 줄 (`N3, N8, N4, N6`) | `[ … ]` | `[ … ]` | *아예 건너뜀 (읽기 0)* |

**② 세 상황 비교 — 왜 '숫자 1개씩 줍기'는 폭망하고, '우리 뉴런 1줄 통째로 줍기'는 빠른가?**
*(GPU는 DRAM에서 최소 `128바이트` = `bf16` 숫자 64개 1박스 단위로만 퍼 온다. `d = 4,096` 기준)*

| 상황 | 메모리에서 집어 오는 모양 | 번호표 대비 유효 읽기 | 버리는 바이트 | RTX 4060 실측 대역폭 · 시간 |
|---|---|---:|---:|---|
| **원래 모델 (다 켬, 쭉 긁기)** | `N1` 줄 → `N2` 줄 → … → `N8` 줄 **전부 100% 연속 읽기** | `100%` | `0%` | `227.4 GB/s` · `1.7705 ms` (`1.00×`) |
| **나쁜 비정형 희소 (숫자 1개씩 줍기)** | `128B` 박스(64개)를 퍼 와서 **숫자 1개(`2B`)만 쓰고 63개 버림** | `1.6%` | **`98.4%` 낭비** | 대역폭 폭락 *(일반 비정형 프루닝이 느린 이유)* |
| **우리 선택 읽기 (뉴런 1줄 통째로 줍기)** | 번호표(`4B`) 1번 보고 **뉴런 1줄(`8 KB = 64박스`)을 쭉 연속 읽기** → 다음 줄로 점프 | **`99.95%`** | **`0%`** | **`213.9 GB/s`** (베이스의 **94%**) · **`0.2824 ms` (`6.27×`)** |

- 비유하자면 창고에서 볼트 1알씩 줍는 게 아니라 **팔레트(뉴런 1줄 = 64박스) 통째로 지게차로 집어 오는 것**과 같다.
- 번호표(`act_ids`)를 보고 점프하는 실제 오버헤드는 대역폭 기준 **약 6%**(`227.4 → 213.9 GB/s`)뿐이고, 대신 읽는 총량이 **85% 줄어들어** 최종 **`6.20 ~ 6.27×`의** 순가속이 실측으로 나온다 *(이 오버헤드까지 모두 포함해 잰 수치다)*.

</details>

## 4단계 · 왜 단일 요청에서는 줄인 비율만큼 곧바로 6배 넘게 빨라지나?

### ① 핵심 물리 원리: 단일 요청은 '메모리 바운드'
토큰이 **1개**뿐이면 GPU가 할 곱셈·덧셈 양은 아주 적고, 대신 거대한 가중치(`d = 4,096` 4층 합 `384 MB`, L2 캐시 `32 MB`의 12배)를 느린 DRAM에서 칩 안으로 **실어 나르는 시간**이 전체 실행 시간의 거의 100%를 차지한다.
- 따라서 **가중치를 `15%`만 읽으면 시간도 이론상 `1 / 0.15 = 6.67배` 가까이 곧바로 줄어든다.**
- 또한 토큰이 1개뿐이라 다른 토큰과 눈치를 맞출 필요가 없어 **빈칸(`×0`)도 `0개`, 타일링도 불필요**하다.

### ② RTX 4060 실제 층별 실측 (`CH2_M32_B1B2_r9`, 순수 `bf16`, 양자화 없음)

실제 시험 토큰 32개 표본(평균 활성 `15.0%`)으로 4개 층 연속 실행 시간을 잰 결과다 *(모든 층이 L2 캐시를 넘기도록 4층 전체 `96 MB / 384 MB`를 이어서 측정)*.

| 층 | 활성 뉴런 (`K`) | `d = 1,024` (실제 `CH2` 가중치) | `d = 4,096` (대형 LLM 층 폭) |
|:---:|---:|---:|---:|
| **1층** | `22.51%` | `0.1164 → 0.0244 ms` (**`4.77×`**) | `0.4426 → 0.1060 ms` (**`4.18×`**) |
| **2층** | `24.12%` | `0.1164 → 0.0274 ms` (**`4.24×`**) | `0.4426 → 0.1131 ms` (**`3.91×`**) |
| **3층** | `12.60%` | `0.1164 → 0.0199 ms` (**`5.85×`**) | `0.4426 → 0.0577 ms` (**`7.67×`**) |
| **4층** | `0.78%` | `0.1164 → 0.0033 ms` (**`34.88×`**) | `0.4426 → 0.0056 ms` (**`78.72×`**) |
| **4개 층 합계** | **`15.0%`** *(10k 평균 `13.52%`)* | **`0.4656 → 0.0751 ms` (`6.20×`)** | **`1.7705 → 0.2824 ms` (`6.27×`)** |

- **`d = 1,024` vs `d = 4,096` 구분:** `d = 1,024`는 실제 학습한 `CH2` 가중치 그대로 잰 결과이고, `d = 4,096`은 같은 `CH2` 출석부와 활성 비율을 7B~8B급 대형 LLM 층 폭에 적용해 순수 커널 속도를 잰 결과다.
- **보수적 표본 & 공정한 베이스:** 실측에 뽑은 무작위 32토큰 표본의 평균 활성률은 `15.0%`(이론 상한 `6.67×`, 전체 10,000장 평균 `13.52%`보다 오히려 보수적 조건)이며, 그 이론 상한의 **94%(`6.27×`)를** 실리콘에서 달성했다. 베이스 시간 역시 `cuBLAS`와 직접 짠 밀집 GEMV 중 **더 빠른 쪽**을 `1.00×` 기준으로 삼았다.

## 5단계 · 다음 문서로 이어지는 질문: 왜 여기서 끝나지 않나?

토큰 1개(`B = 1`, 개인 노트북·온디바이스 생성 단계)는 이렇게 간단하게 **6.20 ~ 6.27배**가 나온다.

**하지만 실제 AI 서버에서는 한 번에 토큰 512 ~ 2,048개가 동시에 들어온다.**
- 중심점 `A`에 속한 토큰(`T1`)은 `{N1, N2, N5, N7}`을 켜야 하고, 중심점 `C`에 속한 토큰(`T5`)은 `{N4, N6, N8}`을 켜야 한다.
- 수백~수천 명의 서로 다른 출석부를 단순하게 합쳐 버리면 결국 8개 뉴런을 전부 다 켜는 꼴이 되어 **속도 이득이 `1.0×`로 붕괴**한다.
- 게다가 대형 배치에서는 메모리 읽기보다 **GPU 텐서 코어의 네모 틀(행렬곱) 연산량**이 시간을 결정한다.

→ 이 **대형 배치의 벽**을 **비격자 5단계 타일링**(`Roster-Tile`)과 **512열 L2 스트립**으로 어떻게 깨부수는지가 바로 다음 문서의 주제다.
