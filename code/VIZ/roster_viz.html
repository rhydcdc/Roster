2 · 연산 만들기 ① 층별 차등 중심점 (M=[32, 32, 32, 256])

1~3층은 중심점 32개로 크게 뭉치고, 4층은 256개로 세밀하게 나눈다

베이스 모델에 학습 사진 2만 장을 넣어 층 입력(1,024칸)을 정규화한 뒤 k-평균으로 중심점을 찍는다. 핵심은 층의 역할에 맞춰 중심점 개수를 다르게 두는 것이다.

  • 1~3층 (M = 32): 대형 배치(B = 512 ~ 2,048)에서 같은 중심점에 평균 16 ~ 64개 토큰이 저절로 모여, 64×32 고속 텐서 코어 틀의 뼈대가 바로 선다.
  • 4층 (M = 256): 분류 직전 층이라 부류별 미세 분기를 유지해야 한다. 256개로 세밀히 나누면 활성 뉴런이 0.80%까지 내려가 4층 단독 15~22배 빨라진다.

중심점은 끝까지 고정된다. 같은 중심점으로 간 입력은 켜는 뉴런이 100% 같아, 추론 전 오프라인으로 모든 타일 인덱스를 미리 만들어 둘 수 있다.

중심점을 처음 찍는 법: 제비뽑기 (k-평균++)

첫 중심점은 점들 가운데 하나를 아무렇게나 고른다. 다음 중심점부터는 점마다 '이미 찍은 중심점 가운데 가장 가까운 것까지의 거리'의 제곱만큼 제비를 넣고, 한 장을 뽑는다.

점가장 가까운 중심점까지 거리제곱 = 제비뽑힐 확률
A11장1/15 ≈ 7%
B11장1/15 ≈ 7%
C24장4/15 ≈ 27%
D39장9/15 = 60%
합15장100%

먼 점일수록 제비가 많아 잘 뽑히지만, 가까운 점이 뽑힐 수도 있다. 이미 중심점인 점은 거리가 0이라 제비가 없다. 이렇게 하면 처음 중심점들이 한쪽에 몰리지 않고 고루 퍼진다. 거리 대신 제곱을 쓰는 것은 먼 점을 더 세게 밀어주기 위해서다(거리 3배 → 확률 9배).

실제 코드도 같다. 1~3층은 32개, 4층은 256개를 찍은 뒤 40번 되풀이하고, 처음 30번 동안은 점이 20개보다 적게 붙은 중심점을 가장 큰 무리 안의 점으로 다시 찍는다.

2 · 연산 만들기 ③ 연산이 하는 일

입력이 오면 층마다: 중심점 내적 1회 → 그 목록의 앞 K개만 켠다

별도 신경망(라우터)이 아니다. 1~3층은 32개, 4층은 256개 중심점과의 거리만 재서 가장 가까운 하나를 고르고, 미리 적어 둔 명단 앞 K개만 켠다.

사진을 바꿔 보면 층마다 가는 중심점과 켜지는 뉴런 자리가 바뀐다. 아직 사후 학습 전(0바퀴)이라 평균 54.2%를 켠다.

게이트·업·다운 세 행렬을 계산하기 전에 켤 뉴런이 확정되므로, 나머지 뉴런은 가중치조차 읽지 않고 통째로 건너뛴다.

3 · 되풀이 ① 타일·블록 친화적 공유 사후 학습 (한 바퀴)

개인 순위뿐 아니라 ‘가족(B1)’과 ‘32열 블록(B2)’ 단위로 함께 앞쪽에 몰아 학습한다

단순히 중심점 개인 순위만 앞쪽으로 몰면 중심점끼리 쓰는 뉴런이 흩어져 서버 배치에서 ×0과 DRAM 읽기가 커진다. 우리는 사후 학습 손실 자체에 하드웨어 타일 구조를 심었다.

  • B1 · OLO 균형 가족 몰기 (α = 0.35): 비슷한 중심점끼리 G=[8,8,8,16] 가족으로 묶어, 같은 가족이 공통으로 많이 쓰는 뉴런을 함께 앞쪽으로 당긴다.
  • B2 · 32열 블록 몰기 (β = 0.25) + Group-L2 (λ_blk = 0.05 → 0): 4,096열을 32열짜리 128개 블록으로 나눠 덜 쓰이는 블록을 통째로 비운다. 빈 블록이 늘수록 DRAM 읽기와 P2 합집합이 같이 줄어든다.

이 코디자인 덕분에 모델 스스로 GPU 텐서 코어가 좋아하는 네모 반듯한 32열 블록 덩어리 형태로 희소해진다. 아래 인터랙티브 격자에서 3단계 차이를 직접 눌러 보라.

3 · 되풀이 ② K 줄이기 (같은 한 바퀴)

학습 없이, 출력 오차 e(k) ≤ ε 가 되는 최소 K로 줄인다

사후 학습 뒤 모델이 실제로 더하는 크기로 목록을 다시 세우고, 앞 k개만 켰을 때 출력 오차 e(k)가 허용치 ε 이하인 가장 작은 k를 새 K로 확정한다.

허용 오차 ε는 검증 정확도 문턱 90.96% 이상을 지키는 값 가운데 가장 많이 줄이는 것으로 고른다(시험 셋은 끝까지 절대 보지 않음).

빽빽한 덩어리는 64×32 · 32×32로 떠내고, 자투리만 8×16으로 마감한다

8×16만 단독으로 돌리면 데이터 재사용이 낮아 텐서 코어가 놀게 된다. 1순위 64×32(cuBLAS의 90%)와 2순위 32×32부터 차례로 떠내야 풀스피드가 나온다.

  • 0단계 (같은 중심점 결집): 1~3층 M=32에서 같은 중심점 토큰(16~64개)은 켜는 뉴런이 100% 같아 0 패딩 없이 64×32 대형 덩어리가 바로 형성된다.
  • 5단계 실측 비용 사다리: RTX 4060 실측 비용(64×32:1680 · 32×32:1024 · 32×16:640 · 16×16:486 · 8×16:410)으로 단위 GPU 시간당 필수 1을 가장 많이 덮는 큰 틀부터 추출한다.
  • 비격자 자유 행·열 짝짓기: BSMR의 고정 행 패널 경계를 없애 타일마다 행과 열을 자유롭게 짝짓는다.

문제 1

0과 1로 된 표가 있습니다. 행 8개, 열 32개입니다. 행 하나에 1은 8개쯤입니다. 행마다 1 가운데 무작위로 고른 하나에 '꺼도 되는 1' 표시가 있습니다.

  1. 1을 묶는 직사각형들을 만들 수 있도록 행과 열의 순서를 마음대로 바꾸십시오. 모든 행과 열을 빠짐없이, 딱 한 번씩만 쓰고, 각 행과 열은 처음 번호를 그대로 달고 옮겨집니다.
  2. 되도록 최대한 많은 1을 직사각형들로 묶으십시오. 직사각형끼리 겹치면 안 됩니다. 직사각형끼리는 붙어 있어도 되고 떨어져 있어도 됩니다.
  3. 직사각형들은 최대한 1로만 이루어지게, 최대한 크게 만드십시오. 직사각형 안에는 최대한 적은 0을 포함시키십시오.
    • 참고: 한 줄짜리(1 × x, x × 1)도 직사각형입니다. 되도록 여러 줄짜리로 만드십시오.
  4. '꺼도 되는 1'은 직사각형을 만드는 데 도움이 되면 끄고, 도움이 안 되면 그대로 두십시오.
    • 참고: 최종 CH2 모델은 공유 사후 학습(B1+B2)만으로 이미 충분히 뭉쳐, 검증 문턱(90.96%)에서 '꺼도 되는 1(1*)' 비율을 0%로 채택해 배치 무관 100% 동일 출력을 달성했다.

문제 2 (5단계 다중 크기 틀 순위 확장)

문제 1에서 만든 직사각형들이 있습니다. 1 × 1도 직사각형입니다. GPU 데이터 재사용률과 실측 실행 비용에 맞춰 우선순위가 매겨진 5단계 틀 목록(RTX 4060 기준 1순위 64×32 → 2순위 32×32 → 3순위 32×16 → 4순위 16×16 → 5순위 8×16)이 있습니다.

  1. (최우선 조건) 틀의 가로줄 하나에는 행 번호 하나만, 세로줄 하나에는 열 번호 하나만 들어갑니다.
    • 예: 줄인 틀(가로줄 2개, 세로줄 4개)로 보면 이렇습니다.
      • 조각 (행 1, 열 1·2)와 조각 (행 1, 열 7·8): 행 번호가 같아서 가로줄 하나에 나란히 들어갑니다. 가로줄 하나가 남습니다.
      • 조각 (행 1, 열 1·2)와 조각 (행 5, 열 7·8): 행 번호가 달라서 가로줄을 하나씩 따로 씁니다. 틀이 다 찼는데 8칸 가운데 4칸은 0으로 채워집니다.
  2. (5단계 틀 순위 조건) 공유 메모리 재사용률이 높은 큰 틀을 앞 순위로 두고 각 틀의 실측 비용을 부여합니다. 빽빽한 덩어리는 1순위(64×32) · 2순위(32×32)로 먼저 찍어 내고, 중간 밀도는 3·4순위(32×16 · 16×16)로, 마지막 성긴 자투리만 5순위(8×16)로 마감합니다.
  3. 표 위에서 모든 필수 1을 빠짐없이, 딱 한 번씩만 찍어 내십시오. 틀을 다 못 채우면 그곳은 0으로 채우며, 전체 실행 비용과 불필요한 0이 최소가 되게 하십시오.
묶기 3 · 실제 서버 4개 층 통계 (CH2 + A3V4)

배치 2,048에서 연산의 86.6%를 64×32·32×32로 묶고 채움률 87.4%를 달성했다

최종 CH2 모델과 A3V4 실시간 디스패처(1*=0%)로 실제 서버 청크(512 / 1,024 / 2,048) 4개 층 전체를 분해한 실측 통계다.

  • 64×32 대형 틀 압도: B=2,048에서 1순위 64×32 단독 비중이 76.7%, 1·2순위 합계가 86.6%에 달한다(저속 8×16은 0.9%).
  • 초고밀도 채움 & 1*=0% 무손실: 타일 안 채움률이 72.6% → 82.3% → 87.4%(×0 단 12.6%)로 치솟고, P1 15.3% · P2 16.1%로 FFN 총 연산량이 15.6%까지 내려갔다.
  • 배치 무관 완전 동일 출력: 10,000장 연쇄 시험에서 B=512 · B=2,048 모두 90.81%(원본 대비 하락 0.00%p, 필수 1 누락 0건)로 비트 수준 동일성을 검증했다.
묶기 4 · L2 열-스트립 캐싱 (DRAM 읽기 절감)

같이 쓰이는 뉴런을 미리 옆자리로 이사시켜, 512열 구역마다 L2에서 1회 읽기로 끝낸다

대형 LLM은 한 층 가중치(96MB)가 L2 캐시(32MB)보다 크다. 4,096열 전체를 넘나들면 L2에서 쫓겨나 DRAM 재읽기가 생긴다.

  • 오프라인 1회 열 재배치(비용 0초): gate · up · down 뉴런 순서를 똑같이 바꿔 저장하면 출력이 100% 같다. 32열 블록 단위 오프라인 정렬로 짝이 맞는 열을 이웃하게 모은다.
  • 512열 × 8구역 L2 상주: 한 구역(약 8MB < L2)을 DRAM에서 1번만 올려 구역 안 타일을 전부 끝내므로 중복 읽기 0%가 고정된다.
  • B2 빈 블록과의 시너지: 공유 사후 학습으로 아예 꺼진 32열 블록이 늘어나, 대형 배치에서도 DRAM 읽기 총량이 64.2 ~ 64.5%까지 추가로 줄어들었다.

묶기 4-B · P2 합집합 최적화(autoTM) & A3V4 실시간 디스패치

P2는 autoTM으로 합집합을 16.1%로 묶고, A3V4 CPU 계획은 1.49~2.83ms로 어텐션 뒤에 완전히 숨긴다

FFN 가속이 실제로 벽시계 속도로 이어지려면 ① 2단계 W_down(P2)의 합집합 폭발을 막고, ② CPU 타일 계획 시간을 밀리초 단위로 끝내야 한다.

  • ① P1 vs P2 비대칭 & autoTM: P1(gate·up)은 타일마다 행·열을 자유롭게 짝짓지만, P2(W_down)는 토큰 블록(TM행) 안의 모든 활성 열 합집합을 거쳐 출력에 더해야 한다. TM을 층 밀도에 맞춰 자동 선택(1~3층 TM=32, 4층 TM=16)하고 B1/B2로 열을 뭉쳐 P2 합집합을 16.1%까지 낮췄다.
  • ② A3V4 AVX2 디스패치 (46초 → 1.49~2.83ms): 중심점이 유한하므로 오프라인 1회(13.1ms) 사전 인덱스를 만들어 두고, 런타임에는 AVX2 무분기 스캔으로 4개 층 계획을 1.49 ~ 2.83ms에 끝낸다.
  • ③ 어텐션 중첩 vs 중첩 없는 직렬 E2E: 표준 트랜스포머에서 d=4,096 1층 어텐션(3.24~13.30ms) 동안 다음 층 A3V4+H2D가 100% 미리 끝나 노출 오버헤드 0.00ms(여유 2.3~6.4×)다. 중첩을 전혀 안 쓰는 보수적 직렬 E2E도 함께 측정해 아래에 분리 보고한다.
묶기 5 · 이론 상한 (Roofline)

실제 서빙 풀 모델 (기준선 = 100%, 1.0배): 뉴런을 다 켠 베이스 모델(91.02%)을 cuBLAS로 계산한다. 1단계(gate·up)와 2단계(down)를 합친 전체 FFN 연산량은 3 × 4 × B × d × 4,096 MAC, DRAM 읽는 양은 뉴런당 1번(4 × 4,096 = 16,384열)이다.

시험 정확도 검증 (10,000장 연쇄 · 1* = 0%): 검증 5,000장 문턱(90.96%)만으로 1* = 0%(opt_00)을 채택했다. 시험 사진 10,000장을 층 1 → 2 → 3 → 4 연쇄로 실제 A3V4 마스크를 적용해 측정한 결과, 단일 요청(B=1), 서버 B=512, 서버 B=2,048 모두 정확히 90.81%(베이스 91.02%의 99.77%, 하락 0.21%p [-0.17, 0.59], 통과선 90.52% 통과; 묶기 전 원본 대비 하락 0.00%p, 필수 1 누락 0건; 실제 활성 뉴런 평균 13.52% [22.07 / 21.67 / 9.55 / 0.80%])로 배치 크기와 무관한 비트 동일 출력을 확인했다.

속도 (Roofline 이론 상한): 전체 FFN 연산 비율 FFN% = (2 × P1% + P2합집합%) / 3과 DRAM 읽기 비율을 기준으로, 연산과 DRAM 읽기가 완전히 겹치는 이상적 한계 max(B, ridge) / max(FFN% × B, 읽기% × ridge)로 계산했다(RTX 4060 ridge 104, A100 ridge 156, H100 ridge 295).

핵심 기여 1 · 구조 — 학습 라우터 없는 층별 차등 중심점 명단

1~3층 M=32 · 4층 M=256 내적 1회로 3개 행렬을 선제 스킵하고, 대형 배치 64×32 결집을 연다

기존 예측기(Deja Vu 등)는 토큰마다 2⁴⁰⁹⁶가지 중 새 패턴을 내 대형 배치에서 붕괴했다. 우리는 유한 중심점으로 패턴 공간을 닫아 두고 모델이 명단에 맞추도록 출발점을 뒤집었다.

  • 학습 라우터 0개 + 3행렬 선제 스킵: 단순 중심점 내적 1회만으로 gate · up · down 세 행렬의 활성 명단을 계산 전 확정하며, 고정 전문가 분할(MoEfication·CMoE)과 달리 공용 뉴런을 자유롭게 공유한다.
  • 층별 차등 M=[32,32,32,256]: 앞 1~3층은 M=32로 배치 512~2,048에서 중심점당 16~64토큰이 자연 결집해 0 패딩 없는 64×32 덩어리를 만들고, 출력 직전 4층은 M=256으로 0.80% 초희소 정밀 분기를 유지한다.

핵심 기여 2 · 사후 학습 코디자인 — 타일·블록 친화적 공유 사후 학습 (B1 + B2)

가족(B1)과 32열 블록(B2) 압력으로 ×0·P2·DRAM을 동시에 깎고, 1*=0% 배치 무관 동일 출력을 달성했다

같은 v4 커널과 A3V4 디스패처 위에서도, 중심점마다 개별 몰기만 한 모델(M=256)은 타일 안 ×0 38.5% · P2 합집합 26.1% · DRAM 83.0%의 벽에 걸렸다.

  • 하드웨어 인식 손실 함수: 결합 순위(0.40 개인 + 0.35 가족 + 0.25 32열블록) + Group-L2(tot_on 정규화)를 적용해 모델 자체가 32열 블록 단위로 뭉쳐 희소해지도록 훈련했다.
  • 같은 커널 위 순수 +47~70% 추가 가속: B=2,048에서 ×0 38.5%→12.6%, P2 26.1%→16.1%, DRAM 83.0%→64.5%, 디스패치 6.81→2.83ms로 모든 병목이 동반 해소되며 GPU 속도가 3.10× → 4.57× (+47.2%) 도약했다.
  • 정확도 상승 + 1*=0% 완전 일관성: 사후 학습 품질이 오히려 올라 시험 정확도 90.81%(99.77%)를 기록했고, 1* 탈락을 0%로 꺼 배치 크기(B=1, 512, 2,048)가 바뀌어도 출력이 100% 같다.

핵심 기여 3 · 타일링 & 실시간 디스패치 — 비격자 5단계 × A3V4 AVX2

고정 행 패널을 깬 비격자 5단계 커버링을 46초에서 1.49~2.83ms로 줄여 어텐션 뒤에 숨겼다

최신 SDDMM(BSMR · Fused3S · TC-GNN)은 고정 행 패널 경계에 묶여 있고, 정밀 비격자 최적화는 수십 초가 걸려 실시간 서빙에 못 썼다.

  • 비격자 5단계 커버링: 행 패널 경계를 깨고 실측 비용 사다리(64×32 → 8×16)로 떠내, 똑같은 CH2 희소 표 위에서도 10회 반복 대조 시 BSMR 5단계 행 패널 상한보다 ×0과 실측 GPU 비용을 크게 앞선다(아래 접이식).
  • 오프라인-인덱스 A3V4 AVX2: 유한 중심점 표가 고정인 점을 활용해 512열 스트립 인덱스를 오프라인(13.1ms)에 구축, 런타임 4층 디스패치를 1.49~2.83ms(16,000배 단축)로 끝내며 오프라인 정밀 솔버와 0.22%p 이내로 일치한다.
실제 CH2 모델 스케일(4층 × 4,096 뉴런) 10회 반복 BSMR 대조 — 정적 · SDDMM(BSMR) vs 우리 A3V4 5단계

공정한 동일 표 대조 (1*=0% · CH2 모델 동일)

  • 모든 대조군(MatFormer · SpMM · BSMR BSA · BSMR OLO · BSMR 5단계 행 패널 상한)에게도 우리의 CH2 희소 표와 OLO 행 정렬을 그대로 제공했다.
  • 그럼에도 고정 행 패널 경계 때문에 B=512~2,048 전 구간에서 우리 비격자 A3V4가 BSMR 5단계 상한보다 ×0·칸 수·실측 비용 모두 압도한다.

1.49~2.83ms A3V4 vs 46초 정밀 ms_solve

  • 오프라인 정밀 솔버(ms_solve)와 실시간 A3V4의 칸 수 격차는 B=2,048 기준 단 0.22%p(15.34% vs 15.56%)에 불과하다.
  • 실행 시간은 46초 → 1.49~2.83ms(16,000배 단축)으로 줄어 대형 LLM 어텐션 뒤에 노출 0.00ms로 완벽히 숨겨진다.
핵심 기여 4 · E2E 실측 검증 — 단일 요청 & 대형 서버 동시 돌파

순수 bf16 실측으로 단일 6.27배, 대형 서버 중첩 4.57배 · 직렬 3.10배를 동시 입증했다

커널 마이크로벤치마크나 단일 요청에만 머무르지 않고, CPU 디스패치 · H2D 전송 · GPU 4층 FFN · 10,000장 연쇄 시험 정확도까지 전체 파이프라인을 동일 GPU에서 검증했다.

  • 단일 요청 (B=1): 타일링 없이 활성 13.52%만 직접 읽어 6.20×(d=1,024) · 6.27×(d=4,096).
  • 대형 서버 (B=512~2,048): d=4,096 어텐션 중첩 3.08× / 4.09× / 4.57×, 중첩 없는 직렬 E2E 1.66× / 2.58× / 3.10×, d=1,024 GPU 3.00× / 3.83× / 4.32×.
  • 양자화 없는 직교 구조: 순수 bf16으로만 달성해 FP8 / INT4 양자화 및 향후 대형 LLM 확장과 그대로 직교 결합된다.
